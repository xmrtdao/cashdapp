### Lesson learned

**The `state.errors` array in `cron-fetch-tasks.mjs` is the canary
for "POST routes that the cron thinks exist but actually don't."
Errors only count when there's a task to dispatch — if 0 pending,
0 errors. So the failure was silent for hours at a time.

The state file lives at `C:/Users/PureTrek/Desktop/relay-data/cron-state.json`
(one directory above the repo) — easy to miss. Should consider
moving it into `relay-data/` or a `state/` dir for visibility.

Also: the `// API: ...` comment convention I use makes route
sections easy to find, but doesn't help me notice when a route
goes missing. Consider adding a route inventory file that gets
regenerated by grepping `app.post`/`app.get` declarations, then
diffed on every commit to catch regressions like this one.

## Alice Inbound Email Parsing — 18:20 CST

Joe asked: "fix and test alice's parsing of inbound emails both
from partyfavorphoto.com and from mobilemonero.com — they should
already be coming into the supabase table, as eliza found the
email in the database, but we need to codify our email
management system".

### State of the system before this session

- **Alice had zero inbound email logic.** She only sent. No
  parsing, no classification, no client management.
- **The relay's `/api/fleet-chat/email-webhook` endpoint was
  the only path populating `email.inbox` state** with parsed
  text — but the actual Resend inbound webhook at the Supabase
  edge function was broken.
- **The `resend-webhook-proxy` edge function** stored email
  metadata only (no body), all emails came in as
  `title='(no subject)'`, `content=''`. 32 garbage rows in
  `inbox_messages`.
- Two parallel inbox systems existed: relay `email.inbox`
  state (working for any webhook the relay receives) and
  Supabase `inbox_messages` (broken at the edge function
  layer).

### What I built

**New module:** `relay/lib/inbound-email-parser.mjs` (510+ LOC)

A standalone ESM module Alice imports. Pipeline:

1. **Read** unread emails from both relay inboxes
   (`/resend/inbox`, `/resend/mobilemonero/inbox`) AND
   Supabase `inbox_messages` (type='email', is_read=false).
2. **Dedupe** by email_id / message_id / from+subject.
3. **Skip** already-parsed entries (parsed_by='alice-sidecar').
4. **Fallback** to Resend's `GET /emails/receiving/{id}` when
   body is empty (for Supabase rows that have an email_id).
5. **Classify** into: inquiry | reply | vendor_pitch |
   automated | support | general. Priority 1-10.
6. **Extract** key client fields: phone, date, guest_count,
   address, event_type, budget.
7. **Persist** parse metadata back to Supabase rows
   (metadata.parsed_by, category, priority, extracted).
8. **Mark** relay emails as parsed via new endpoint.
9. **Create task** in `tasks` table for inquiries + support
   emails, with full extracted fields in metadata.
10. **Idempotent** — safe to run every cycle.

**New relay endpoint:** `POST /resend/inbox/parsed`
Stores classification + extraction on the relay's email state
entry so future runs skip them.

**Alice wiring:** parser runs between `fleet-autopilot` and
`fetchAndRouteTasks` in the main cycle. Result count is saved
to alice-state.json and surfaced in the 3rd-cycle fleet chat
summary.
