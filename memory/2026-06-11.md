# 2026-06-11

## ai-chat redirect (final)

Joe: "I thought we were using ai-chat ... when did we start using eliza-relay?" → "yes skip eliza-relay and include ai-chat"

### What was wrong
`relayToElizaCloud()` in `relay/server.js:1219` was POSTing to `${SUPABASE_URL}/functions/v1/eliza-relay` — the deprecated 25-line stub. Joe's question was correct: the local stack has been serving `ai-chat` (the 4864-line live EF with provider cascade, conversation memory, tool execution) for months, and we should be calling it.

### The fix (commit 7ff9e4e)
- `relayToElizaCloud()`: URL `/functions/v1/eliza-relay` → `/functions/v1/ai-chat`
- Request body: `{ action, message, relay_tag, agent_name }` → `{ userQuery, senderName, session_id }` (ai-chat's actual schema)
- Response normalization: `data.content → data.reply` so all 4 downstream callers work without code changes
- Fleet-chat branch pre-fetches `gatherFleetContext()` and embeds the JSON in `userQuery`

### Persona-dump detection (the catch)
ai-chat's `generateSystemPrompt()` at `suite/supabase/functions/ai-chat/index.ts:4049` is hardcoded. It always dumps the "I'm Eliza, General Intelligence Agent for XMRT-DAO" persona intro. Cannot be overridden from request body. First test: ai-chat got a "just say pong" instruction and still did the full persona dump in 6579ms.

Solution: grounding-marker detection. The reply must cite at least one field from the grounding JSON (supabase|ollama|hermes|github|uptime|models?|cpu|memory|supervisor|relay) to NOT be considered a persona dump. If those markers are missing AND the reply starts with a greeting/intro pattern OR contains "i'm eliza"/"general intelligence" OR is longer than 250 chars → trigger deepseek fallback through `/ollama/chat` with `deepseek-v4-flash:cloud`.
