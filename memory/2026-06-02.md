### Critical bug found during testing

The markdown function was placed inside the big `res.send(\`<!DOCTYPE html>` template literal that starts at line 1388. The function's `//` comment contained literal backticks (`` // Supports: \`code\`, \`\`\`code blocks\`\`\` ``), and the regex literals used backticks. V8's parser doesn't recognize `//` comments as comments when it's inside an open template literal — backticks there flip it into template-literal-parsing mode, which then derails the entire parse. V8 errored at line 2093 (the next `const SUPABASE_URL = '${...}'`), making the bug look unrelated to my code.

Fix: replaced all literal backticks in the function's regexes with `\x60` hex escapes (`\x60` = `` ` ``). The regex engine still sees the real character at runtime, but the source code has no literal backticks anywhere in the open template literal. Also rewrote the `//` comment to use `[apostrophe]code[apostrophe]` style instead of backticks.

Tested the renderer in isolation: all 3 test cases (formatted post, XSS attempt, mixed formatting) produce correct sanitized HTML. Relay restarted (PID 2164), health green, no parse errors. Articles post on the board will now render with proper headings, tables, lists, and bold text.

### General lesson
**Never put a function definition (or any code with backticks) inside a giant `res.send(\`...\`)` HTML template literal.** Move helpers to a separate file or define them before the route handler. The template-literal context changes how `//` comments parse, and V8 won't tell you where the real problem is — it'll fail at the next `const FOO = '${...}'` and you'll spend 30 minutes chasing the wrong line.
